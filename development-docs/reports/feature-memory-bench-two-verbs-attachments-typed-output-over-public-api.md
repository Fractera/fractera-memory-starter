## 3. Главная находка — механический поиск без ИИ не работает на русском

`lib/verbs.mjs`, `recall`: «слова вопроса — против слов в имени рода». Имена родов английские фразы (`city_where_he_lives_now`), вопросы человека
русские. **Совпадение невозможно по построению** — каждый русский вопрос уходит в ветку «точного совпадения нет — вот всё, что известно».
На шести фактах это выглядит как ответ; на сотнях — ответа не будет, и обещание владельца «большую часть доставать без ИИ мгновенно»
на русских вопросах **не исполняется**.
🛑 **Не измерено, выведено из кода:** в английских вопросах возможны ложные совпадения по служебным словам имени рода (`he`, `with`, `us`).

## 4. Оценка всей работы памяти

**Что работает хорошо и доказано:**
- **Запись.** 14 из 14: разбор фразы, нить с дешёвым продолжением, опровержение внутри нити, охват, требование таблицы, вложения трёх родов и файл,
  проверки рода и формы. Цена — ход модели на запись: 5–12 с на фразу, 24–74 с со вложением.
- **Договор.** Две двери, одна схема ответа, порождённая из кода; каждый отказ говорит словами и проходит схему.
- **Чтение фактов мгновенно и без ИИ:** 0,1–0,4 с.
- **Поиск объектов по смыслу точен:** документ и ролик найдены с первого места за 0,5–1,1 с — но это встраивание, то есть ИИ.
- **Не выдумывает:** на вопрос о несуществующей собаке факт не рождён.

**Что не работает — по весу:**
1. **Точность чтения фактов на русском** — механика без ИИ не находит (раздел 3). 7 из 9 «неправильно» — отсюда.
2. **Нет честного «не знаю»:** вопрос без совпадения отдаёт всё известное.
3. **Объекты:** нет механической ступени (только встраивание), нет фильтра по `who` и по роду намерения — ТЗ `200-9` в очереди.
4. **`depth: deep/extreme` на фактах не делает ничего** (`depth_used: 1`) — названо честно, но обещание без исполнения.
5. **Уборка** `forget(ids)` оставляет строки сообщений и документы графа → повторная ссылка отвечает `existing` при удалённом объекте.
6. **Род ролика** — `youtube` при записи и `web` при чтении.

## 5. Нужен ли новый цикл правки навыков?

**Нет — не сейчас.** Доводы:
1. **Все найденные дефекты — в коде чёрного ящика, а не в поведении агента.** Матрица шла прямо в `/v1/*`, мимо агента; ни один навык на эти
   девять «неправильно» не влияет. Правка навыков не поднимет ни одной из этих строк.
2. **Прошлые испытания навыков показали малый прирост при высокой цене:** 189-10 — различие в 2 случаях из 4; 192-5 — 94 % с навыком против
   81 % без; 193 — 100 % и с навыком, и без. Цикл прогонов сжёг две сессии владельца, подагенты запрещены.
3. **Единственный незамеренный вопрос о навыках** — вызовет ли агент навык сам, без подсказанного пути, — дёшево не меряется и на качество ящика не влияет.

**Что даст более высокие показатели — шаг кода «точность без ИИ», затем та же матрица как прибор регресса:**
1. **Опоры рода на языке человека.** Слова-триггеры создаются один раз при записи — модель там уже зовётся. Чтение остаётся без ИИ.
2. **Честное «не знаю»** вместо выдачи всего; «всё известное» — только по явной просьбе.
3. **200-9:** механическая ступень для объектов, фильтр по `who` и роду намерения, `found_by` у каждого объекта.
4. **Выравнять род ролика; уборка по строке сообщения.**
5. **Прибор 200-7 — со строгой оценкой** «в ответе ровно нужный факт», а не «нужный факт где-то среди».

Цикл навыков имеет смысл после этого и только если журналы агента (бот, Telegram) покажут, что агент зовёт не те руки. Проверять чтением
журналов, без подагентов (закон проекта).
