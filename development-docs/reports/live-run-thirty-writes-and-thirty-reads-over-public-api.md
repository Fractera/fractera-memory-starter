## Что сделано по дефектам сразу (решение владельца «Сначала чинить, потом прогон»)

Коммит `7d93918`, на сервере с 01:04 UTC. Правило §21.1 теперь исполняет код (`lib/write-gate.mjs`), а не только подсказка:
разбор JSON в ограде с хвостом (①) · поле `shape: value|story`, рассказ — только в граф (②④) · род вне реестра ложится в таблицу только
коротким значением ≤5 слов (②③) · у текущего признака одна фраза даёт одно значение (③). Отсеянное не теряется — оно в документе графа и в
ответе полем `kept_in_graph_only`. Прибор ворот без модели (`scripts/probe/write-gate-201-9.mjs`) на ответах из этого захода — 10/10.

🛑 **Не проверено моделью:** подчиняется ли модель новому полю `shape`. Это покажет только повторный заход 30+30 после сброса квоты.

## Вопросы на завтра — чтобы делать выводы, а не догадки

1. **Квота.** Один полный заход 30+30 стоит ~70 ходов подписки, и окно общее с ботом. Разбивать заход на части по окнам или ставить памяти
   отдельный ключ/подписку?
2. **Судья записи.** Оставить мягкий («легло куда-то») или строгий («легло верным родом, коротким значением, без рассказа в таблице»)?
3. **Новые роды.** Порог «≤5 слов» выбран по живым примерам, а не измерен. Разрешать ли новые роды вообще, или только реестр + граф?
4. **Объекты.** Прибор оставил в хранилище 3 объекта (txt, md, csv): удаления объекта договор не объявляет. Нужен ли такой метод для приборов?
