# 205-3 — чужой ключ не теряется; признаки принимает и чтение

**Коммиты:** `fractera-memory-starter`, ветка `new-step-205` — `9f2da4a` (подсказка, `features` у `recall`, договор 2.12.0, прибор),
`5636210` (`used_model` по факту, `rejected` в ответе `recall`, схема ответа). **Доставлено:** `5636210`, `BUILD_RC=0`, порт за 3 с.
**Дата:** 2026-09-15.

## Что делали и как

- `lib/features-discover.mjs` → `suggestNearest(rejected)`: отказу `unknown-feature` добавляются до трёх ближайших ключей памяти — поиск по
  словам самого ключа в индексе действующих признаков, без модели — и слова «вероятно, имелся в виду …». Зовут `discover()` и запись
  (`verbs.mjs`, присланные признаки). Псевдонимов ключей нет (решение агента в плане: второе имя разошлось бы с первым молча).
- `recall` читает `features` и передаёт их в `discover` — подбор модели пропускается; отказы подбора едут в ответ полем `rejected`.
- Договор 2.12.0: `features` у `recall`; `nearest` в отказе. Схема ответа `recall` описывает `rejected`.

## Доказательства

**A — без модели, на сервере (`scripts/probe/features-given-205-3.mjs`, дословно, фрагмент):**
```
  1 · person.name → person.name-he-is-called, person.nationality-he-names-for-himself
  1 · person.active-hours → person.work-hours-he-keeps-each-day, person.time-zone-he-lives-in
  1 · person.important-people → person.people-he-calls-his-friends, person.meetings-he-had-with-people, person.name-he-is-called
✓ ключ памяти в подсказке (первые 3): 14 из 14 · первым: 14 из 14
✓ НЕГАТИВ: ключ памяти принят без подсказки (taken 1, отказов 0)
```
Доказывает: на любой из 14 ключей чата память называет ключ из утверждённой переписи первым. Без правки отказ был «признака «person.name» в
реестре нет» — и всё.

**B — живое чтение от пустого ключа прибора, без записи (дословно):**
```
✓ recall с признаком → 200, used_model false
✓ recall с ключом чата → 200, подсказка ключа памяти в ответе: true
✓ НЕГАТИВ: recall без признака → 200, used_model true
===PROBE_205_3=== всё сошлось 2026-09-15T16:13:25.930Z
```
Доказывает: признак, присланный зовущим, избавляет чтение от вызова модели, а чужой ключ возвращается с подсказкой. Квота названа владельцу
до прогона (последний отказ `five_hour` 00:45 UTC); прибор сделал один вызов модели — в негативе.

## Ошибки

- ✗ **Дефект, найденный прибором: в трёх ответах `recall` после подбора `used_model: true` было вписано руками.** Подбор с присланным
  признаком модель не звал, а ответ говорил «звалась» — уверенное ложное значение (закон 144). Первый прогон B: `used_model true` при
  признаке. Исправлено: `meant.used_model === true`.
- ✗ **Отказы подбора не выносились ни в один ответ `recall`** — подсказка рождалась и терялась. Переменная `refused` объявлена до `answer`:
  ранние выходы зовут его раньше подбора.
- Пропущенный импорт `suggestNearest` в `verbs.mjs` пойман до запуска чтением правки.
- 🛑 **Прибор оставил след в живой памяти, хотя «только читал»:** `recall` зовёт `rowOf(who)`, а тот делает `INSERT OR IGNORE` строки
  человека (`lib/store.mjs:195`). Чтение от ключа `probe-205-3` завело пустую строку `probe-205-3` в корневой таблице. Двери уборки строки
  нет. Вероятно, так же родились и 10 строк людей корневой таблицы. Урок: «прибор ничего не пишет» проверяется по коду каждой двери, которую
  он зовёт, а не по имени глагола.
- Проверку «ключ памяти первым» я заранее ослабил до «в первых трёх»; вышло 14 из 14 первым — ослабление не понадобилось.
