## Что делали и как

- **Паспорт памяти §21 «Схема в центре»:** определение реестра признаков словом владельца первой строкой · его слова дословно · куда
  ложится сказанное (граф получает всё; таблица — точное, счётное, текущее; указатель из графа в таблицу) · правило глубины §3п чата законом
  памяти, одна копия со ссылкой на источник и с явным «что §21 добавляет к §3п» · реестр `AGI-CONFIG` (смысл наружу, не место; признак не есть
  имя таблицы — закон API §2 в силе) · подбор схемы: кандидаты по смыслу → один `claude -p` без нити → код проверяет тип и собирает запрос ·
  чтение · паритет · что меняется в §4/§8 и чего не трогает · чего раздел не решает. Отсылки в §3, §4 (надгробие обещания «без ИИ»), §8.
- **Снята прежняя подсветка паспорта** (31 строка `==…==` прошлых сессий) — правило самого паспорта «следующая сессия снимает прежнюю».
- **`BLACKBOX-API.md`:** в §3 — «⬜ Шаг 201: что изменится снаружи» (планируемое отдельно от построенного), имена полей и маршрутов намеренно
  не названы — появятся в договоре; в §4 — какие три «не умеет» шаг берёт на себя.
- **Паспорт чата §3р «Синхронизация с памятью»:** определение владельца первой строкой · пять решений (реестр — словарь памяти; хозяин
  фактов — память; шлётся смысл без `storedIn`; признаки — ускорение, память проверяет тип; договор — из `GET /v1/contract`, не из нашего
  репозитория) · таблица «что есть сегодня → к чему приводится» · порядок снятия (память доказала → чат переключил → переезд данных словом
  владельца → надгробия) · чего решение не касается (автоматизации, календарь, геометки, охват, реестр инструментов). Надгробия-указатели в
  §3о и §3п, строка карты разделов. **Раздел написан целиком в паспорте чата, потому что §7 чата запрещает его агенту читать чужие деревья.**
- **Доставка на сервер:** паспорт памяти — файлом (страница читает его с диска, сборка не нужна; `DELIVERED_COMMIT` оставлен `455e53d` —
  код не менялся); клон чата `/opt/fractera/telegrambot` доведён `git merge --ff-only` с `9724c93` до `990ecc4` (разница — только паспорт).
