## Откуда
Сверка API v1: `media` принималось и молча выбрасывалось. Владелец: «Делай полный вариант: методы объектов в API»;
на вопрос о `media` — «Через ingest».

## Что делали и как
- `lib/fractera/fetch-url.ts`: скачивание по `http`/`https`; проверяется **адрес, в который разрешилось имя** — в
  `lookup` самого соединения (петля, частные сети, link-local, служебные диапазоны, адреса машины); буквальный IP —
  до соединения; каждое перенаправление заново; предел 200 МБ; ответ `text/html` → `is-a-page` (граница с шагом 195).
- Дверь `object-ingest`: к форме добавлен JSON с `url`, дальше тот же `ingest()`; ответ несёт итоговый `url`.
- `server.mjs`: `/v1/keep_object` проводит по петле и форму, и JSON; иное тело — `unsupported-body`.
- `lib/media-ingest.mjs` + `lib/verbs.mjs`: вложения `remember` уходят по одному в `object-ingest` с секретом машины
  **до разбора фразы** — файл ложится, даже если фактов во фразе нет; судьба каждого — в `objects` любого ответа.
  `lib/store.mjs` отдаёт `machineEnv` общим.
- `lib/params.mjs`: у `media` появился исполнитель; закон «род называет зовущий» и `MEDIA_KINDS` сняты надгробием —
  род определяет `kindOf`, одно правило на хранилище. `contract.mjs` 2.4.0: `keep_object` `body: "multipart | json"`,
  параметр `url`, новые отказы; у `remember` — `objects`.

## Доказательства
**A — сеть снаружи, положительные пути** (`node scripts/probe/v1-objects.mjs`, публичный адрес, ключ памяти):
```
✓ договор 2.4.0: keep_object body=multipart | json, есть file и url
✓ по адресу: 200 messageId 29 described false url https://www.fractera.ai/404.jpg
✓ по адресу: размер 286835 = 286835, род image
remember: 200 objects=[{"error":"url-forbidden",…"url":"http://127.0.0.1:3300/health"},{"id":"87bb1742-…","kind":"markdown","messageId":30,"ok":true,…}]
✓ вложение README → ok, messageId 30, род markdown
```
Доказывает: файл, названный адресом, память скачала сама байт в байт и положила; вложение фразы легло тем же путём
и названо в ответе. Без правки: `JSON` в `/v1/keep_object` давал `not-multipart`, `media` отвечало `accepted`
и не делало ничего.

**B — негатив, тот же прибор:**
```
✓ адрес http://127.0.0.1:3300/health → 400 url-forbidden
✓ адрес http://localhost:3700/v1/health → 400 url-forbidden
✓ адрес http://169.254.169.254/latest/meta-data/ → 400 url-forbidden
✓ адрес ftp://example.com/file.txt → 400 bad-url
✓ адрес https://www.fractera.ai/ → 400 is-a-page
✓ после отказов по адресу новых строк нет · вложение в петлю → url-forbidden
✓ уборка: строк убрано 3, документов графа было 3, осталось 0 · ✓ OK · PROBE_RC=0
```

Доказывает: чужой зовущий не достаёт руками памяти ни слой данных, ни саму память, ни адрес метаданных облака;
страница не выдаётся за файл. Весь прибор 194-15 при этом остался зелёным.

## Ошибки
- **Первый прогон оставил в живом графе три документа прибора**: уборка ждала разбора одного документа, а удаляла три —
  два свежих движок молча не удалил (находка 194-4). Опознаны чтением (только `object/…` без строки таблицы, все три
  от прибора), удалены, проверено: граф 0, файлы 0, карточки 0, строки 0. Уборка прибора теперь ждёт разбора каждого
  документа и удаляет с повторами — второй прогон убрал всё.
- **След, который прибор не убирает намеренно:** два вызова `remember` оставили по записи в журнале памяти.
  `forget_journal` стирает журнал целиком, то есть и живую историю владельца, — поэтому не вызывается.
