# 195-7 — память зовёт ИИ-браузер через «одну дверь» слоя данных

**Коммиты:** `ai-workspace` `ca085bc` (слой данных) · `fractera-memory-starter` `d67127b` (ветка `new-step-195`). **Дата:** 2026-09-14.
**На сервере:** `/opt/fractera/DEPLOYED_COMMIT` = `ca085bcc`, `/opt/fractera/memory/DELIVERED_COMMIT` = `d67127b`.

## Откуда взялась задача
Владелец посреди 195-1 спросил, не ходит ли память во внутренности браузера мимо его API. Измерено: не ходит (0 обращений к коду
браузера), но зовёт договор `/v1/read` прямым портом, а в «одной двери» слоя данных браузера не было. Выбор владельца — **«Маршрут
слоя данных»**.

## Что делали и как
- **Слой данных** (`services/data/server.js`): `ai-browser` в `INTERNAL` (адрес по умолчанию в коде, установщик не трогается);
  маршрут `/service/ai-browser/*` под `requireAuth`, секрет машины браузеру подставляет слой; предел ожидания прокси — параметр
  (по умолчанию 120 с, у браузера 600 с).
- **Найдено чтением до правки:** образец хвоста `^\/service\/[a-z]+` не знает дефиса — `/service/ai-browser/v1/read` ушёл бы в
  браузер как `-browser/v1/read`. Образец стал `[a-z-]+`; для трёх прежних имён равнозначен.
- **Память** (`lib/fractera/web.ts`): `readLinks` зовёт `dataService().url + /service/ai-browser/v1/read` тем же ключом, что данные.
  Отказы различены по тому, кто молчит: `data-unreachable` (слой данных) · `browser-unreachable` (слой ответил `503 … did not answer`).
- Доставка: слой данных — `git merge --ff-only origin/main` в `/opt/fractera` + `pm2 reload fractera-data`; память —
  `deliver-memory.sh 74e002e` (один файл кода).

## Доказательства
**1. Дверь слоя данных (плоскость HTTP на сервере).**
- Запущено: `curl` на `127.0.0.1:3300` до и после перезапуска слоя; прямой `POST /service/ai-browser/v1/read` с секретом машины.
- Вывод: до — `/service/ai-browser/v1/health 404`, после — `200`; соседи до = после: `rag/health 200`, `geo/ 404`, `channels/ 404`;
  без секрета `{"error":"Unauthorized"} HTTP=401`; с секретом `HTTP=200 results=1 title=HTML: HyperText Markup Language | MDN
  text_length=7872`. Порт 3300 держит pid pm2 `1289355`.
- Доказывает: маршрут существует, закрыт замком слоя, пропускает к браузеру секретом, не сломал соседние двери.
- Без правки: `404` на двери браузера; с прежним образцом хвоста — отказ браузера на пути `-browser/v1/read`.

**2. Путь памяти (плоскость собранного кода и прибора через публичный адрес).**
- Запущено: `grep` по `.next/server` памяти; `node scripts/probe/link-test.mjs` через `https://memory.aifa.dev`.
- Вывод: `build_service_route=2`, `build_direct_port=0` (негатив: прямого адреса браузера в сборке нет); прибор `✓ OK` — MDN и TodoMVC
  открыты (заголовки, текст 7872 и 657, полей у TodoMVC 2), `401` без секрета, `url-forbidden` на `127.0.0.1:3300`, `400
  too-many-urls`, строк 5 / векторов 38 до = после. Порт 3700 держит pid pm2 `1289743`; движок `up`, зависаний 0.
- Доказывает: стенд ссылок работает прежним образом, а путь к браузеру идёт только через слой данных.
- Без правки: в сборке `127.0.0.1:3800` ≥ 1.

## Ошибки
- Первая редакция комментария в `web.ts` цитировала номер порта — `grep 3800` насчитал бы «живой» адрес в надгробии (закон 78-5
  «надгробие пишется пересказом»). Переписано пересказом до коммита.
- 🛑 **Не проверено:** отказ `browser-unreachable` живьём — нужна остановка ИИ-браузера (запрещено ради проверки).
