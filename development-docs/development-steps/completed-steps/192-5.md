## Доказательства

**A — прогон skill-creator, признаки названы до прогона** (итерация 2, `benchmark.md`):
```
| Pass Rate | With Skill 94% ± 12% | Without Skill 81% ± 24% | +0.12 |

    ✓ Открыто не больше одного документа, который не оказался ответом — 1

    ✗ Ответ называет предел поиска объектов — назван неверный механизм «по общему смыслу»
    ✗ Открыто не больше одного документа, который не оказался ответом — 3
```
**Негативный контроль** — базовая линия без навыка. Различие есть в одном случае из четырёх и
устойчиво на двух прогонах. Два случая не различают ничего, и это записано как результат: их держит
конструкция.

**B — корпус и руки настоящие:** журналы вызовов содержат дословные выдачи сервера (id вида
`f8056618-4b70-…` совпадают с `192-5-corpus-ids.txt`, снятым с `GET object-test`). Объекты, сохранённые
прогонами через `keep_object`, существовали в медиатеке и убраны по id после прогона:
`{"removed":2}` ×2. В складе снова ровно 32 объекта корпуса, всего в медиатеке 37 = 32 + 5 чужих.

## Ошибки

- `base64 -d` отдал JSON без перевода строки, MCP-сервер строку не увидел, первый вызов обёртки
  вернул пусто. Исправлено `{ …; echo; }`.
- Разбор журнала принимал заголовки Markdown из открытых документов (`### Шаг 0 …`) за вызовы рук.
  Узнаётся теперь по метке времени — тот же класс, что «цитата кода неотличима от кода для прибора».
- Агрегатор skill-creator отдал нули: он ждёт раскладку `eval-N/<конфигурация>/run-1/`, а я разложил
  по-своему. Итерация 1 переложена.
- **Признак 4.4 выбран неудачно** — несовместим с обязательными полями ответа по инструкции агента.
  Оставлен неизменным, назван в отчёте.

- **Сам навык** прошёл две редакции. Первая повторяла то, что уже говорят выдачи рук, — ужата.
  Добавлено правило о слабых попаданиях у порога: оно единственное дало различие в вызовах.

  тратить ходы. Что держит код, навык не повторяет.

  на содержании, без живых рук.
