**Состав 21 записи:** 14 живых родов корневой таблицы (сопоставлены один в один) + 6 признаков из реестра чата, которых у памяти не было
(форма обращения, тон, длина ответа, валюта, запреты, национальность) + траты. Остальные 8 признаков `person.*` чата оказались дублями живых
родов и сведены в них, с перенесёнными словами человека.

🔒 **`storedIn` НЕТ И БЫТЬ НЕ МОЖЕТ, И ЭТО РЕШЕНО КОНСТРУКЦИЕЙ, А НЕ ЗАПРЕТОМ В ТЕКСТЕ.** Род выводится **из ключа**:
`person.city-where-he-lives-now` → `city_where_he_lives_now`. Второй правды о месте не существует — ей негде разойтись с первой.
🔒 **СЛОВАРИ ЗАКРЫТЫЕ:** тип значения (8), накопление (3), субъект (1), глубина (0 и 1), метки (10). Открытый словарь через месяц содержит
`string`, `str` и `текст`, и проверка значения перестаёт что-либо значить.
🔒 **ОДИН ФАЙЛ ПЛЮС ПОРОЖДЁННЫЙ УКАЗАТЕЛЬ** — по измерению соседней службы (157-5): выигрыш даёт указатель, а дробление на файл-на-запись
дороже монолита на самом частом вопросе «что вообще есть».

**Решение, принятое агентом и названное вслух:** у трат `aggregate: "sum-able"`, а не `"list"`, как сказано в ТЗ. `sum-able` — это `list`,
который ещё и складывается; плоским списком кейс владельца («сколько я потратил сегодня» → 900) не выражается. Определение записано в
`lib/features.mjs` рядом со словарём.
**Долг, названный в самой записи:** `person.age-he-is-now` живёт, хотя §21.2 велит хранить год рождения. Род живой, под ним есть записи;
снятие — решение владельца.

## Доказательства

**A — живая дверь на сервере (`node scripts/probe/features-201-3.mjs` в `/opt/fractera/memory`):**
```
✓ живой реестр валиден: записей 21, нарушений 0
✓ GET /v1/features → 200, записей 21 из 21
✓ GET /v1/features/money.spent-on-a-purchase → 200, накопление sum-able
✓ живых родов 14, покрыто признаками 14
```
Доказывает: реестр читается снаружи через публичный API и покрывает всё, что память уже ведёт. Без правки `/v1/features` отвечал `501 not-built`
(ровно это и печатал прибор до переноса маршрутов).

**B — негативные контроли, три разной природы:**
1. *сторож видит плохое* — 11 испорченных записей подряд, каждая роняет его поимённо: без типа · тип вне словаря · накопление вне словаря ·
   **`storedIn`** · ключ `Цвет; DROP TABLE x` · глубина 2 · пустые триггеры · метка вне словаря · субъект вне словаря · повтор ключа ·
   два ключа с одним родом. Эталонная запись при этом принята (0 нарушений) — сторож не «ругается всегда».
2. *сборка падает на плохом реестре* — `MEMORY_AGI_CONFIG_DIR=<копия с storedIn> npm run build` → код `1`; тот же `npm run build` на живом
   реестре → `0`. Значит сторож стоит именно в сборке, а не рядом с ней.
3. *в ответе двери нет места хранения* — счёт совпадений `person_who_owns_this_project` в теле `/v1/features` = **0**, `storedIn` = 0;
   несуществующий ключ → `404 unknown-feature`; выдуманные роды в покрытии не числятся.

🛑 **Не проверено глазами:** вкладка «API» на `memory.aifa.dev` — она порождается из `CATALOGUE`, и живой договор её уже отдаёт
(`version 2.8.0`, `catalogue 5`, оба адреса реестра в списке), но саму страницу владелец ещё не видел.

## Ошибки

- ✗ **Маршруты были дописаны в `server.js`, который никто не запускает.** Живой вход — `server.mjs` (он же в `package.json`, он же под pm2);
  `server.js` остался от поколения «служба без Next» и содержит **вторую копию** маршрутизатора `/v1/*`. Поймал прибор на сервере:
  `GET /v1/features → 501 not-built` при зелёной сборке. Правка из мёртвого файла снята, маршруты перенесены.
  🔒 **Урок шире случая:** файл с именем, которое выглядит точкой входа, и с рабочим кодом внутри — ловушка ровно того же класса, что
  «два списка одной способности»; прибор на живой двери его ловит, чтение кода — нет. Судьбу `server.js` решает владелец: он мёртв, но
  удаление файла службы — не самовольная уборка.
- Мелкая попутная: `npm run check` теперь зовёт обоих сторожей (договора и реестра) — прежде второго не существовало.

## Эволюция навыков

Читались `use-development-steps` и (в этой сессии впервые) его scoped-вариант памяти. Тормоз один и он же ошибка выше: ни в `CLAUDE.md`
памяти, ни в паспорте не сказано, **какой файл является входом службы** — в дереве два похожих, и выбор пал на неверный. Предложение для
201-8: строка в `CLAUDE.md` памяти «вход — `server.mjs`; `server.js` — мёртвое наследие, маршруты в него не дописывать».
