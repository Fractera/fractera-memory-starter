# 203-4 — установщик ставит память целиком, как на тест-сервере

**Коммиты:** `fractera-easy-starter` `main` — `671df71` (`main == origin/main`); `fractera-memory-starter` `main` перемотан на `5e5f452`
(вливание 201 → 202 → 204 → 203). **Дата:** 2026-09-15.

## Что делали и как

- Основание — паспорт памяти §0 п. 1, слово владельца: «на запуске пользователей получает устойчиво работоспособной память».
- Разведка: `bootstrap.sh:1065–1073` клонировал память без `--branch` и запускал `server.js` без установки и сборки; ветка по умолчанию на
  GitHub — `main`, а `main` стоял на `455e53d` без 201–204. Решение владельца формой: **«Влить всё в main сейчас (Recommended)»** — вливание
  прошло перемоткой, ветки 201, 202, 204 оказались предками 203.
- Блок памяти: клон `--branch main` · `memory_deps` — `pnpm install --frozen-lockfile` · `memory_build` — `pnpm build` · `memory_start` —
  `pm2 start server.mjs`, ожидание `/v1/health` до 60 проверок. Все шаги мягкие; соседние не тронуты. Комментарий «нет зависимостей»
  пересказан как история, без цитаты старой команды. `bash -n` — `BASH_N_OK`.
- 🛑 FES отправлен **только после** зелёного чистого клона: отправка сразу даёт установщик новым серверам.

## Доказательства

**A — чистый клон на тест-сервере теми же командами** (`/tmp/memory-203-4`, порт 3799, своё имя pm2; живая `/opt/fractera/memory` не
тронута), журнал дословно:
```
CLONE_RC=0 head=5e5f452
INSTALL_RC=0            (Done in 8.8s using pnpm v10.32.1)
BUILD_RC=0
PM2_START_RC=0
HEALTH_UP=after 4 s
health: 200
build_page_http=200 bytes=316748
build_page_workspace_attr=1
---NEGATIVE old server.js on 3798---
neg health: 200
neg_build_page_http=404
neg_workspace_attr=0
live memory 3700 health: 200
tmp removed: yes
```
Доказывает: новый блок из чистого клона `main` даёт службу со страницами (мастерская отвечает 200 и несёт свой атрибут). **Негатив** —
прежний вход `server.js` из той же папки: здоровье отвечает, мастерской нет (404) — ровно то, что получал бы новый сервер без правки.

**B — установщик в GitHub:** `fractera-easy-starter` `main` = `origin/main` = `671df71`.
🛑 **Названное заранее доказательство «установщик, отданный Vercel» недостижимо агенту:** `lib/deploy.ts:90` читает `bootstrap.sh` из
собранного приложения (`process.cwd()/lib`) и выгружает его на сервер по SSH — публичного адреса у отданного файла нет. Замена B
доказывает, что код в источнике, и **не доказывает, что Vercel собрал этот коммит** — это видно только в панели Vercel владельца.
🛑 **Рождение нового сервера** — действие владельца; не выполнялось.

## Ошибки

- Негативный процесс `node server.js` пережил `kill $!` в фоновом скрипте и держал порт 3798 после удаления папки — снят отдельным
  заходом по своей командной строке (`cwd=/tmp/memory-203-4 (deleted)`), чужих процессов не касались.
- Параллельные вызовы оболочки дважды за подшаг выполнились в чужой рабочей папке (гонка `cd`) — локальные проверки повторены с
  абсолютными путями.
- `pnpm-workspace.yaml` памяти несёт заготовку `allowBuilds: sharp: set this to true or false` — чистую установку она не сломала; оставлена.

## Эволюция навыков

- `memory-development` §Delivery говорит о доставке файлами; для установщика добавить нечего — закон «новый сервер = тест-сервер» живёт в
  паспорте §0 и федеральном `CLAUDE.md`.
- Приём, стоящий переноса: долгую проверку на сервере запускать в фоне с журналом и дочитывать отдельными заходами — обёртка SSH
  возвращается раньше долгого процесса.
