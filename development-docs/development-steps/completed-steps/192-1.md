# 192-1 — клиент объектного хранилища и три двери

**Репозиторий:** `fractera-memory-starter`, ветка `new-step-192`. **Коммит кода:** `1b48daa`.
**Доставлено на сервер:** 2026-09-13, сборка `BUILD_RC=0`, порт 3700 поднят за 4 с, слушатель — процесс pm2.

## Что делали и как

Объектное хранилище не пришлось строить: оно уже есть у платформы — медиатека слоя данных
(`/media/*`, файл на диске и строка с `id`). У неё нет поиска вовсе, поэтому объект **находится по
карточке**: имя + описание словами загрузившего + у текстового объекта первые 1500 знаков. Карточка
ложится в векторный склад своей коллекцией `memory-objects` со ссылкой `ref_table=media`,
`ref_id=<id>` — поля для этого в складе уже были. Отсюда у объектов есть число близости и честное
«ничего подходящего».

- `lib/fractera/objects.ts` — `keep` · `find` · `open` · `status` · `forget`;
- двери `object-test` (GET/POST multipart/DELETE), `object-search`, `object-open` — замок `benchGuard`;
- имена трёх дверей названы привратнику `proxy.ts` до первой сборки;
- скрипт доставки `/code/scripts/deliver-memory.sh <base>` — `git archive` изменённых файлов → `scp` →
  `tar` → сборка под `flock` с кодом сборки → `pm2 reload` → порт по факту.

**Принадлежность — по карточке в нашей коллекции, а не по имени.** В той же медиатеке лежат снимки
Telegram и значки проекта; `open` и `forget` отказывают чужому поимённо (`not-ours`, `refused`).

## Доказательства

**A — живой вызов дверей на сервере секретом машины** (`scripts/.deliver-memory/p1.sh`):
```
A1 keep   {"cardChars":1514,"ms":4503,"object":{"id":"79a1487f-…","mime":"text/markdown","name":"acr.md","size":13351,"text":true},"ok":true}
A2 search «как решается, какой системе отдать входящее сообщение из телеграма»
          found True threshold 0.28 askMs 3171 → 0.352 79a1487f-… acr.md
A3 NEG    «рецепт борща со свёклой и сметаной» → found False nearest 0.027
A4 open   ok True shown 12000 total 13250 head: # Agent channel routing — …
A5 NEG    open чужого id медиатеки → {"error":"not-ours","ok":false}
A6 NEG    двоичный без описания → {"error":"no-about","ok":false}
A7 NEG    ключ памяти на двери стенда → 401
```
Доказывает: объект кладётся, находится вопросом **другими словами и на другом языке** (документ
английский, вопрос русский), открывается текстом с названным пределом. Без правки дверей не было бы
вовсе — `404`.

**B — слой данных напрямую, мимо наших дверей:**
```
исходный файл             76a0ba4502a0…ecbd464d71
GET /media/<id>/file      76a0ba4502a0…ecbd464d71
vectors                   obj-79a1487f-… · memory-objects · media · ref_id=79a1487f-… · 1514
DELETE {ids:[свой, чужой]} → {"ok":true,"refused":["6a34395f-…"],"removed":1}
media до  и после         те же пять чужих id; карточек в memory-objects: 0
```
Доказывает: файл лёг байт в байт, карточка связана с ним ссылкой, уборка унесла только своё.
Негатив уборки: чужой id в списке назван отказом, и пять объектов медиатеки не тронуты.

## Ошибки

- heredoc с обратными кавычками в Markdown ТЗ разорвал оболочку (`unexpected EOF`) — файлы ТЗ
  переписаны редактором. Закон проекта сработал ровно так, как записан: знание его не исполнило.
- **Не ошибка, а открытый вопрос в 192-2:** поиск занял 3171 мс против 170–400 мс у вектора в 189.
  Кандидаты: первый вызов модели встраиваний `large`, полный список медиатеки на каждый поиск.
  Не называю причину до замера.
- Попутно: в предел `open` считаются знаки строки (13250), а `size` — байты (13351); это разные
  единицы, и в ответе они названы разными полями.

## Эволюция навыков

Читались `use-development-steps` (федеральный) и образцы `vectors.ts`/`vector-test`. Тормоза не было:
форма соседей переносится на объекты почти дословно, и именно поэтому решение «карточка в векторе»
нашлось за одно чтение `server.js` — поля `ref_table/ref_id` были предусмотрены заранее. Улучшать
навыки нечего.
