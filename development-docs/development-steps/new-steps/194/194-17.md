# 194-17 — чтение объектов снаружи: `find_objects`, `open_object`, файл по `GET /v1/objects/{id}/file`

## 0. Откуда подшаг
Слово владельца «Делай полный вариант: методы объектов в API»: положить без возможности найти — половина способности.

## 1. Что строится
- `contract.mjs`: методы `find_objects` (`question`, `k`) и `open_object` (`id`, `from`) — JSON, те же имена, что у рук
  агента: одно имя на одно дело. Адрес каталога `GET /v1/objects/{id}/file` — байты с `Content-Type`.
- `server.mjs`: три пути по петле в существующие двери `object-search`, `object-open`, `object-file`; ответ проходит
  насквозь.
- Ответ `find_objects` несёт у каждого найденного `messageId`, род и саммари — чтобы зовущий не открывал всё подряд.

## 2. Что считается готовым
Объект, положенный в 194-15, находится вопросом по смыслу через публичный адрес, открывается полным описанием, а его
файл скачивается байт в байт.

## 3. Чем доказывается — названо заранее
- **A (сеть):** прибор: `find_objects` → id из 194-15 в выдаче; `open_object` → полное описание; `sha256` скачанного
  файла = `sha256` отправленного.
- **B (негатив):** вопрос из заведомо несуществующего слова → `found: false`; чужой id → `404`; без ключа → `401`.

## 4. На что опирается
194-15.

## 5. Чего в подшаг не входит
Удаление объекта через API (`forget`) — не просили; остаётся за стендом.
