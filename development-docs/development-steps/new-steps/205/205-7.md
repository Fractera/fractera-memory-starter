# 205-7 — вкладка реестра в настройках чата показывает реестр памяти

## 1. Что строится
- `fractera-telegrambot-starter/app/[lang]/settings/_components/facts-registry.tsx`: список признаков берётся из каталога памяти через одну
  дверь слоя данных (`/service/memory/v1/features`), а не из `REGISTRY-CONFIG`; у признака — ключ памяти, метка навыка и отметка
  «подключён к чату». Если память недоступна — вкладка говорит это словами.
- Текст задачи «добавить признак» (`facts-handoff-text.ts`) адресует реестр памяти и панель `admin.<домен>/feature-registry`.
- Над списком — одна строка: механизмы (род входа, намерение, куда уехало, дата, место, связь) — не признаки, память ведёт их сама.
- `REGISTRY-CONFIG` чата не удаляется; его README получает указатель на реестр памяти (надгробие — после переключения кода чата).

## 2. Что считается готовым
Вкладка реестра на `chat.aifa.dev` показывает 23 признака с ключами памяти вместо 49 записей чата.

## 3. Чем доказывается (названо заранее)
- **Плоскость 1 — отданная страница:** счёт `data-feature-key="person.name-he-is-called"` ≥ 1; **негатив** — `data-feature-key="person.name"`
  (ключ чата) = 0.
- **Плоскость 2 — отказ по-честному:** при остановленной выдаче каталога (подмена адреса двери на заведомо неверный в приборе, не в живом
  окружении) компонент отдаёт строку «реестр памяти недоступен», а не пустой список.

## 4. На что опирается
205-5 (одна дверь).

## 5. Чего в подшаг не входит
Переключение записи и чтения фактов чата на память · удаление `fact_person_*` и `lib/facts/*`.
