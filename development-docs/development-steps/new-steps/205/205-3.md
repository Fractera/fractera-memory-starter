# 205-3 — чужой ключ не теряется; признаки принимает и чтение

## 1. Что строится
- `lib/features-discover.mjs` → `checkGiven`: неизвестный ключ получает в отказе `nearest` — до 3 ближайших ключей памяти по смыслу
  (индекс реестра `lib/features-index.mjs`, без модели) и слова «признака `person.name` нет; вероятно, вы имели в виду
  `person.name-he-is-called`». Фраза при этом разбирается как обычно — отказ признака не отменяет сохранения.
- `contract.mjs` + `lib/verbs.mjs` → `recall`: необязательный `features` (ключи памяти) сужает чтение и пропускает вызов модели;
  версия MINOR.

## 2. Что считается готовым
`remember` с `features: [{key:"person.name", value:"Рома"}]` отвечает отказом с подсказкой `person.name-he-is-called` и всё равно
сохраняет фразу.

## 3. Чем доказывается (названо заранее)
- **Плоскость 1 — функция без сети:** прибор `scripts/probe/features-given-205-3.mjs` зовёт `checkGiven` на 14 ключах чата — у каждого в
  `nearest` первым стоит ключ из утверждённой переписи; **негатив** — ключ памяти принят без `nearest`.
- **Плоскость 2 — живые двери на сервере** (квота названа, метка прибора, уборка своего): `remember` с ключом чата → `rejected[0].nearest`
  содержит ключ памяти, `kept_whole.ok = true`; `recall` с `features: [{key:"money.spent-on-a-purchase"}]` → `used_model: false`;
  **негатив** — тот же `recall` без `features` → `used_model: true`.

## 4. На что опирается
205-1.

## 5. Чего в подшаг не входит
Псевдонимы ключей (решение агента — не заводить) · переключение чата на ключи памяти.
