# 205-6 — страница панели «Реестр признаков»

## 1. Что строится
- `ai-workspace/bridges/app/lib/admin-nav.ts`: строка `{ slug: "feature-registry", group: "data" }`.
- `bridges/app/app/[lang]/feature-registry/page.tsx` (серверная): читает каталог и подключения через одну дверь слоя данных; показывает
  23 признака — название, тип, накопление, при отсутствии значения, метка навыка (зелёная — есть, красная — будет создан), подключённые
  элементы; фильтр по элементу.
- Островок подключения: выбор элемента и галочки признаков → `PUT` через дверь панели `app/api/config/feature-registry` (под `requireAuth`,
  `// @api`), которая зовёт одну дверь слоя данных.
- Словарь `admin-translations.json`: `pages["feature-registry"]` и строки страницы — `en` и `ru`; островку — только его слова пропсами.

## 2. Что считается готовым
На `admin.aifa.dev/ru/feature-registry` владелец видит 23 признака и подключает к чату признак, и подключение появляется в каталоге памяти.

## 3. Чем доказывается (названо заранее)
- **Плоскость 1 — отданная страница:** счёт строк признаков по атрибуту `data-feature-key="` = 23; **негатив** — без сессии архитектора
  `curl` получает 307 на вход.
- **Плоскость 2 — сохранение сквозь двери:** дверь панели `PUT` элементу-прибору → `GET /service/memory/v1/features/consumers` возвращает
  набор; уборка своего. Глазами — страница предъявляется владельцу (согласование построенной поверхности).

## 4. На что опирается
205-5 (дверь и подключения).
