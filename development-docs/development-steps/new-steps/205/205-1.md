# 205-1 — полная форма записи реестра памяти

## 1. Что строится
- `lib/features.mjs`: новые необязательные поля записи и закрытые словари — `onMissing` (`silent` · `ask` · `join`), `askOrder` (число),
  `example` (текст), `lost` (что теряется), `scope` (ключи охвата: `time`, `place`), `skills` (`have: [...]`, `plan`), `requires` (ключи
  признаков памяти). Сторож `problemsOf` проверяет их по словарям; `publicFeature` отдаёт их наружу.
- `AGI-CONFIG/agi-config.json`: 20 записей дополнены из утверждённой переписи (14 фактов о человеке — поля чата: `onMissing`, `askOrder`,
  `example`, `lost`); `index.json` порождается заново.
- `contract.mjs`: описание каталога называет новые поля; версия MINOR.

## 2. Что считается готовым
`GET /v1/features/person.name-he-is-called` отдаёт «при отсутствии — спросить», порядок вопроса 2 и пример.

## 3. Чем доказывается (названо заранее)
- **Плоскость 1 — сторож в сборке:** `node scripts/check-features.mjs` — 0 нарушений на живом реестре; **негатив** — копия с
  `onMissing: "maybe"` и с `skills.have` на несуществующий навык роняет сторож поимённо.
- **Плоскость 2 — живая дверь на сервере после доставки:** `GET /v1/features/person.name-he-is-called` → `onMissing: ask`, `askOrder: 2`;
  **негатив** — `GET /v1/features/person.name` → `404 unknown-feature`.

## 4. На что опирается
Утверждённая перепись `205-census.md`.

## 5. Чего в подшаг не входит
Новые признаки (205-2) · поведение записи при чужом ключе (205-3) · навыки (205-8).
