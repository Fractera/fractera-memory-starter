## 3. Решения агента (предъявляются в плане)

- **Определения признаков — в файле реестра памяти; подключения элементов к признакам — данными памяти.** Доставка перезаписывает файлы на
  сервере: подключение, сохранённое панелью в файл, пропало бы со следующей доставкой и не попало бы в git (закон 0 федерального слоя:
  определение в папке, данные в платформе).
- **Одна память — одни ключи.** Псевдонимов ключей чата не заводим: чужой ключ получает отказ с подсказкой ближайших ключей памяти.
  Второе имя одного признака разошлось бы с первым молча.
- **Возраст — долг, а не удаление:** признак помечается снятым, живые значения не трогаются; перенос в дату — отдельным словом владельца.
- **Новая дверь `/service/memory/*`** — по образцу ИИ-браузера (секрет машины подставляет слой). Дверь аддитивная, соседей не меняет.

## 4. Известные ограничения

- **Правка двери — решение владельца** (федеральный закон): `/service/memory/*` предъявляется в этом плане.
- **Словарь панели серверный, 82 языка:** ни один `"use client"` не импортирует словарь; `en` и `ru` пишет агент, остальные — файлом.
- **Реестр читается на каждом запросе с диска** — правка файла видна после доставки без пересборки; сторож реестра стоит в `pnpm build`.
- **Колонка — не таблица:** новый признак рождает род через `addColumn`; `SELECT *` по таблицам признаков запрещён.
- **Квота подписки общая с ботом:** 205-2, 205-3, 205-9 зовут модель — остаток называется до прогона.
- **Приборы убирают только своё** — живая память владельца не стирается.
- **Паспорт → строка инструкции → код** (паспорт памяти, «Как мы здесь работаем»): правила 205-4 сначала в паспорт.
- **Вкладка чата — чужой продукт:** её агент не читает чужих деревьев (§7 чата); всё нужное чату — через договор памяти по сети.
