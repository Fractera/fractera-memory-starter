# 205-12 — публичные тексты приводятся к тому, что есть в коде

## Откуда взялась задача

Владелец 2026-09-15, дословно: **«правь публичные тексты — README и главную, readme use english»**. Сказано в ответ на долг, названный
подшагом 205-11: сверка `205-11-audit.md` нашла на публичной поверхности обещания, которых код не держит.

🛑 **Честно о порядке: ТЗ написано ПОСЛЕ работы, а не до.** Указание владельца было прямым и однозначным, предмет правки — готовый список из
сверки, и я начал править сразу. Закон «подшаг развёрнут в файл до первой строки» здесь не исполнен; записываю это здесь, а не умалчиваю.

## 1. Что строится

1. **README.md (английский, по слову владельца).** Каждое утверждение из §1.2 сверки либо исправляется, либо получает пометку прямо в абзаце.
2. **Главная `memory.<домен>` (ru и en).** То же самое в `app/[lang]/_i18n/landing.i18n.ts`, и для этого у раздела страницы появляется место
   под пометку — поле `building` и блок под лидом в `_components/landing.tsx`.
3. **Форма пометки одна и говорит ДВЕ вещи:** что есть сегодня и что предстоит. Одно «в разработке» без «что есть» читается как «не работает
   ничего» — это обратная ложь, не лучше прежней.

## 2. Что считается готовым

Человек, читающий README или главную и потом открывающий службу, не обнаруживает ни одной способности, которой нет. Владелец читает оба
текста и утверждает.

## 3. Чем доказывается (названо заранее)

- **Плоскость 1 — счёт по исходникам:** каждая ложная строка из сверки даёт 0 совпадений; число пометок больше нуля. **Негатив:** поиск по
  заведомо живой строке (например, «one short model call») обязан давать не ноль — иначе счётчик слеп.
- **Плоскость 2 — живая страница на сервере:** `/{ru,en}` отдают пометки разделов, и прежних обещаний в отданном HTML нет.
- Гейты: `npx tsc --noEmit`, `npm run check`, прибор ссылок `§N`.

## 4. На что опирается

`205-11-audit.md` — таблица «утверждение → адрес в коде → верно/неверно». Ни одного нового утверждения о памяти здесь не вводится.

## 5. Чего в подшаг не входит

Код службы и её поведение · паспорт (закрыт 205-11) · `capabilities.json` и `llms.txt` — они порождаются из тех же слов и проверяются
отдельно, если разойдутся.
