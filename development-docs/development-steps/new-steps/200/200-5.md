# 200-5 — проверка каждого элемента экрана против каждого метода API и отчёт

## 1. Что строится
- **Прибор `scripts/probe/memory-test-matrix.mjs`** — через дверь стенда (значит через `/v1/*`): каждый из 8 методов с каждым параметром по
  отдельности и строки каталога; у каждого метода негатив (без обязательного, неверный тип, неизвестный метод); запись идёт от метки `probe-200`,
  уборка по ней. **До прибора измеряется**, чем убираются строки, записанные `remember` (иначе прибор оставит следы в живой памяти).
- **Живой обход экрана в Chrome владельца** расширением: выбор каждого метода, каждый орган формы, панель «что уедет», отправка, лента ответа,
  таблицы; фиксируется, совпало ли отправленное с набранным.
- **Отчёт** `development-docs/reports/feature-memory-playground-over-public-api-matrix.md`: матрица «элемент × метод» с исходом, код, время,
  цена в ходах модели; непрошедшее — с причиной.

## 2. Что считается готовым
Для каждого элемента экрана и каждого метода договора в отчёте есть строка с измеренным исходом.

## 3. Чем доказывается
- **A:** прибор `✓` по всем строкам матрицы; обход в Chrome — снимки и счёт совпадений отправленного с набранным.
- **B (негатив):** у каждого метода есть отрицательная строка с отказом договора; после уборки состав живых таблиц памяти до = после.

## 4. На что опирается
200-1 … 200-4.

## 5. Чего не входит
`forget_journal` на живом журнале — только по отдельному слову владельца (иначе строка матрицы проверяет подтверждение, а не стирание).
