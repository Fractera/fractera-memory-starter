# 200-2 — экран стенда порождается из договора: все 8 методов и каталог

## 1. Что строится
- `memory-test.client.tsx` — выбор метода из `METHODS` (порождается, не перечисляется) и каталога чтения; форма собирается по `params` метода:
  тип (`string`, `array`, `boolean`, `binary`), обязательность, описание из договора как подсказка.
- Нынешние органы (`memory-test-controls.client.tsx`: глубина, история, нить, цепочка, охват, отрицание, `need_table`) остаются живыми
  редакторами для своих параметров — форма зовёт их по имени параметра, а незнакомый параметр получает общий редактор по типу.
- «Сказать» и «Спросить» — быстрые входы в `remember` и `recall`; «Сырой вызов» — любой метод телом JSON.
- Панель «что уедет» показывает адрес и тело ровно как их отправит дверь (200-1); лента ответов — код, время, сырой ответ.
- Таблицы («Что память построила») читаются через `GET /v1/tables` и `/v1/tables/{имя}`.

## 2. Что считается готовым
У каждого из 8 методов и у каждой строки каталога на экране есть форма со всеми параметрами договора; метод, добавленный в договор, появляется без
правки экрана.

## 3. Чем доказывается
- **A:** в собранной странице — имена всех 8 методов и всех 26 параметров из `contract.mjs` (счёт по сборке = счёт по договору).
- **B (негатив):** временный девятый метод, добавленный в договор только на ветке прибора, появляется на экране без правки клиента; убран — исчезает.
  Глазами владельца — выбор метода и формы.
