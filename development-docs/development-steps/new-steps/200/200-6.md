# 200-6 — проверка каждого органа у обоих глаголов через API и отчёт

## 1. Что строится
- **Прогон в Chrome владельца** (скрипт в странице, уступка хода через `MessageChannel`): для каждого органа × «Сказать»/«Спросить» —
  выставить значение органом, сверить тело панели «что уедет», отправить, записать код `/v1`, время, `params`/`objects` ответа.
  Число ходов модели называется владельцу ДО прогона; писать — от метки `probe-200` у служебного имени `bench-1`.
- **Негативы:** обязательное пусто (`remember` без фразы → `missing-params` договора) · орган у чужого глагола → «не доезжает» и не в теле ·
  «Сырой вызов» (если остаётся) с неизвестным именем → `501 not-built`.
- **Сверка пути:** журнал nginx — у каждого вызова пара «браузер → дверь стенда» и «сервер → `/v1/*`».
- **Отчёт** `development-docs/reports/feature-memory-bench-two-verbs-advanced-params-over-public-api.md`: матрица «орган × глагол» — исход,
  код, мс, ходы модели; непрошедшее — с причиной.

## 2. Что считается готовым
Для каждого органа у каждого глагола в отчёте строка с измеренным исходом.

## 3. Чем доказывается
- **A:** матрица полная (органов × 2 строк), у каждой строки пара в журнале nginx.
- **B:** у каждого глагола отрицательная строка с отказом договора; после уборки записи прибора сняты, и названо, что осталось.

## 4. На что опирается
200-3, 200-4, 200-5.

## 5. Чего не входит
`forget_journal`; методы сверх двух глаголов; стенды других хранилищ.
