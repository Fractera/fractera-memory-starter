# 200-7 — проверка каждого органа у обоих глаголов через API и отчёт

## 1. Что строится
- **Прогон в Chrome владельца** (скрипт в странице, уступка хода через `MessageChannel`): каждый орган расширенных параметров и каждое
  вложение (кнопки родов, две ссылки) × «Сказать»/«Спросить» — выставить значение, сверить тело панели «что уедет», отправить, записать код
  `/v1`, время, `params`/`objects`, соответствие ответа схеме `output`. Число ходов модели называется владельцу ДО прогона; запись — от метки
  `probe-200` у служебного имени `bench-1`.
- **Негативы:** «Сказать» без фразы → `missing-params` договора · орган у чужого глагола → «не доезжает» и не в теле · ссылка чужого рода →
  отказ · неподдерживаемый род файла → `describe-kind-unsupported`.
- **Сверка пути:** журнал nginx — у каждого вызова пара «браузер → дверь стенда» и «сервер → `/v1/*`».
- **Отчёт** `development-docs/reports/feature-memory-bench-two-verbs-attachments-typed-output-over-public-api.md`: матрица «орган × глагол» —
  исход, код, мс, ходы модели, схема; непрошедшее — с причиной.

## 2. Что считается готовым
Для каждого органа и каждого рода вложения у каждого глагола в отчёте строка с измеренным исходом.

## 3. Чем доказывается
- **A:** матрица полная, у каждой строки пара в журнале nginx и отметка «ответ по схеме».
- **B:** у каждого глагола отрицательные строки с отказом договора; после уборки записи прибора сняты, и названо, что осталось.
