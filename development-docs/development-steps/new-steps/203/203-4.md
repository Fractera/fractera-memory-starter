Основание — паспорт §0 п. 1, слово владельца 2026-09-15: «на запуске пользователей получает устойчиво работоспособной память».

## 1. Что строится
- Блок памяти в `bootstrap.sh`: после `memory_clone` — мягкие шаги установки зависимостей (`pnpm install --frozen-lockfile`) и сборки
  (`pnpm build`, код выхода у `pnpm`, лог в файл); запуск `pm2 start server.mjs --name fractera-memory` вместо `server.js`; ожидание
  `/v1/health` по факту остаётся. Команды сверяются с `/code/scripts/deliver-memory.sh` и блоком ИИ-браузера (`:1081+`), где та же схема уже
  работает.
- Все шаги `soft_step` (сервер без памяти — работающий сервер и строка в журнале); соседние шаги не меняются. Комментарий над блоком —
  пересказ причины, без цитаты старой команды (закон 78-5 / 191).
- Пуш FES → сборка Vercel.

## 2. Что считается готовым
Блок памяти установщика, выполненный на чистом клоне, даёт службу со страницами: `/v1/health` отвечает 200 и `/ru/build` отдаётся.

## 3. Чем доказывается (названо заранее)
- **Плоскость 1 — чистый клон на тест-сервере:** команды нового блока дословно, но в `/tmp/memory-203-4` и на `PORT=3799` под отдельным
  именем pm2 (живая `/opt/fractera/memory` не трогается; после — `pm2 delete` своего имени и удаление своей папки): `/v1/health` → 200,
  `/ru/build` с секретом машины → 200 с разметкой мастерской. **Негатив:** в той же папке `node server.js` на `3798` — `/ru/build` не
  отдаётся (старый блок давал неполную службу).
- **Плоскость 2 — установщик, отданный Vercel:** `curl` по адресу, откуда сервер получает `bootstrap.sh` → строка `server.mjs` в блоке
  памяти есть; **негатив:** прежняя команда запуска `server.js` — 0; `git merge-base --is-ancestor` коммита.
- 🛑 **Недостижимое:** рождение нового сервера — действие владельца; называется вслух и не подменяется.
