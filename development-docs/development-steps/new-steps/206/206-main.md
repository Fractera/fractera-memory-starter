# Шаг памяти 206 — «Память живёт одной таблицей»

## 1. Откуда шаг

Решение владельца 2026-09-15, дословно:

> «Восемь весь день работаем над памятью, разом переписываю инструкции , мы зашли в тупик потому что я
> решил твою работу с реестром признаков. Более того я хочу чтобы наша память вообще прекратила работать
> с какими-либо специализированными таблицами кроме одной-единственной который фиксирует все входящие
> сообщения и записи от базы данных. Мы её уже сделали. Таким образом что бы не говорили другие
> пользователи памятник не создают свои таблицы и не читают другие кроме одной единственной таблицы
> сообщений. Почему это будет сделано? Потому что будут другие приложения которые будут заниматься
> этими задачами а память это события вокруг базе для обычной таблицы которые можно создаем для граф
> для вектора и для въездного хранилища то есть всё делаем проще понятнее быстрее с фокусом на
> интеллект агенты которые этим занимаются».

Предыдущее решение того же дня — реестр признаков удалён целиком (`27a9bf7`, договор 3.0.0).

## 3. Развилки, которые решает владелец (форма задана 2026-09-15)

1. Что делать с уже записанным в корневой и дочерних таблицах.
2. Считать ли `__links` и `__registry` частью той же единственной таблицы.
3. Куда ложится разобранный факт из фразы.
4. Судьба `memory_bench_cases`.

Ответы записываются сюда дословно, затем разворачиваются подшаги и план предъявляется формой (этап 9).

## 4. Ответы владельца на развилки, дословно (2026-09-15, форма)

1. Старые данные: **«Удалить вместе с кодом»**.
2. Что считается одной таблицей: **«Да, это одна таблица (Recommended)»** — `messages` вместе с
   `__links` и `__registry`.
3. Куда ложится факт: **«Граф + вектор, сообщение остаётся источником (Recommended) // but we have max
   2000 words for vector and for lightRAG , if more only for object store»**.
4. Бенч-таблица: **«Убрать тоже»**.

🔒 Из ответа 3 рождается порог, которого в коде сегодня нет вовсе (проверено: в `lib/` есть только
`NEW_KIND_MAX_WORDS = 5` у ворот записи): **до 2000 слов — граф и вектор; длиннее — только объектное
хранилище**, а граф держит ссылку на объект.

## 6. Чего в шаг НЕ входит

- Другие приложения, которые займутся специализированными таблицами, — они снаружи памяти.
- Перенос старых данных: владелец выбрал удаление, а не миграцию.
- Переделка самих графа, вектора и объектного хранилища — они принимают события как есть.
- Правка Telegram-службы и панели под новый договор: панель уже избавлена от раздела реестра
  (`ai-workspace` `cb6faf9`), остальное — отдельным шагом, если всплывёт.

## 7. Решения, принятые агентом самостоятельно

- `messages__links` и `messages__registry` остаются: они хранят части того же сообщения (ответ 2).
- Порог 2000 слов считается по словам самого текста, а не по байтам, — так его назвал владелец.
- Ворота записи `lib/write-gate.mjs` не правятся, а **снимаются**: они решали «колонка или таблица»,
  а этого выбора больше нет.
