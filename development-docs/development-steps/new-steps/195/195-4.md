# 195-4 — YouTube по ссылке: данные ролика гарантированно, официальным API по ключу, без браузера и расширения

🔒 **Переписано 2026-09-14 по вопросу владельца** (дословно — в `current-steps.md`): «…теперь это будет обычная серверное действие которое не
будет требовать расширение… и будет работать гарантированно в рамках всех лимитов которые мне дает Google? И мы можем это сейчас запланировать
сделать?». 🪦 Прежняя редакция: ролик шёл в `POST /v1/youtube` ИИ-браузера, расшифровка — там же; без 198 — «что досталось + причина».
Расшифровка вынесена в 195-12 (лучшей попыткой).
**Первоисточник Google:** квота по умолчанию — «10,000 units per day combined for all other endpoints», `videos.list` — «a quota cost of 1
unit»; `captions.download` чужого ролика — `403` («requires the user to have permission to edit the video»). **Измерено:** ключей Google/YouTube
на сервере нет ни в складе секретов, ни в окружении памяти и ИИ-браузера.

## 1. Что строится
- Карточка «Ключ YouTube Data API» в «Настройках» памяти — по образцу карточки ключа OpenAI (181-1): ключ живёт в складе секретов машины
  (`YOUTUBE_API_KEY`), экран показывает только «ключ есть / нет»; проверка ключа живым `videos.list` на эталонном ролике.
- `lib/fractera/youtube.ts` — узнать ролик по адресу (`watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/`); `videos.list`
  (`snippet,contentDetails,statistics`) по ключу; снимок-Markdown: название, канал, дата, длительность, описание целиком, теги, язык,
  статистика, есть ли у ролика субтитры; отказы поимённо: `youtube-key-missing`, `youtube-key-rejected`, `youtube-quota`, `video-not-found`.
- Стенд ссылок: адрес ролика идёт этим путём, а не браузером; «Получить описание» и «Сохранить в память» — те же двери и тот же `keep()`
  (раскладка по хранилищам как у любого объекта, слово владельца «абсолютно одинаковое решение»).

## 2. Что считается готовым
Ссылка на любой открытый ролик YouTube на стенде даёт данные ролика за секунды без браузера, описывается и ложится в четыре хранилища; без ключа,
с плохим ключом, при исчерпанной квоте и на несуществующий ролик — названный отказ.

## 3. Чем доказывается — названо заранее
- **A (прибор через публичный адрес, `scripts/probe/youtube-data.mjs`):** эталонный открытый ролик → данные (название, канал, длительность,
  описание) за < 3 с, браузер не звался (журнал ИИ-браузера без обращения); сохранение → строка `kind=web`, `url` ролика, граф и вектор.
  **Отдельно измеряется:** хватает ли одного ключа API без входа Google для открытых данных — первоисточник этого прямо не говорит.
- **B (негатив):** несуществующий идентификатор → `video-not-found`, записи нет; заведомо неверный ключ → `youtube-key-rejected`; без ключа →
  `youtube-key-missing`; квота не тратится на адрес, который не ролик.

## 4. На что опирается
195-2 (сохранение), ключ YouTube Data API от владельца.

## 5. Чего не входит
Расшифровка (195-12) · поиск новых роликов и лента каналов (будущий шаг, `search.list` — 100 вызовов в день) · комментарии и подписки (горизонт,
не задача).
