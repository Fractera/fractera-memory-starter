# 195-9 — защита от страницы, которую сайт не отдал: код 400 и выше не описывается и не сохраняется

## Откуда взялась задача
Владелец 2026-09-14 показал на стенде ссылок `https://neon.com/blog/an-agent-provisions-a-neon-backend-a-human-claims-it-later` →
«Vercel Security Checkpoint», код 403. Измерено: Vercel проверяет адрес сервера (`x-vercel-mitigated: challenge`). Найденный риск: дверь
описания не смотрит на код — заглушка легла бы в память под адресом статьи. Слово владельца, дословно: «да, делай защиту от 403 и потом оценку».
Маршрутизация: исход A — та же способность шага 195.

## 1. Что строится
- `lib/fractera/web.ts` — `pageRefusal(status, title)`: код ≥ 400 → `{ error: "page-refused", why: "<код> · <заголовок>" }`;
  `statusOfSnapshot(snapshot)` — код из строки снимка `- Код ответа: NNN`.
- `app/api/fractera/link-test/describe/route.ts` — отказ `422 page-refused` до снимка и до модели.
- `app/api/fractera/link-ingest/route.ts` — отказ `422 page-refused`, если снимок несёт код ≥ 400 (защита от прямого вызова двери).
- `link-bench.client.tsx` — у страницы с кодом ≥ 400 вместо «Получить описание» строка словами с кодом и причиной; слова en/ru.

## 2. Что считается готовым
Страница с кодом 400 и выше не описывается и не сохраняется: экран говорит почему, двери отказывают с кодом и причиной.

## 3. Чем доказывается — названо заранее
- **A (прибор через публичный адрес, `scripts/probe/link-page-refused.mjs`, без модели):** `https://httpbin.org/status/403` → дверь описания
  `422 page-refused`, в причине код 403; снимок с «Код ответа: 403» в дверь сохранения → `422 page-refused`; строк таблицы до = после.
- **B (негатив — защита не режет хорошее):** снимок с «Код ответа: 200» проходит ворота и доходит до хранилищ (пустые якоря → откат
  `graph-refused`, строка `failed` убирается по метке прибора). **Глазами владельца** — карточка заглушки на стенде без кнопок, с причиной.

## 4. На что опирается
195-2.

## 5. Чего не входит
Проверки на ботов с кодом 200 (например, страница «Just a moment…») — не распознаются, названо · обход проверки Vercel и ожидание её
прохождения в браузере (федеральный 198) · отказ `page-refused` на странице API — вместе с методом `keep_links` (195-3).
