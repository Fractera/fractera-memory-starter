# 195-12 — расшифровка ролика лучшей попыткой поверх гарантированных данных (195-4)

## Откуда взялась задача
Разделение потоков YouTube 2026-09-14 (вопрос владельца о гарантированном серверном пути — `current-steps.md`). Первоисточник Google: субтитры
чужого ролика официальным API не скачиваются (`captions.download` — только с правом редактировать видео, иначе `403`). Значит расшифровка — не
гарантия, а попытка, и данные ролика не должны от неё зависеть.

## 1. Что строится
- К ролику, уже прочитанному по API (195-4), память пробует расшифровку по очереди: ИИ-браузер `/v1/youtube` через «одну дверь» слоя данных
  (перехват ответа плеера, 196-4) → путь федерального шага 198 («Панель расшифровки», выбор владельца), когда он будет построен → запасной
  Chrome владельца (шаг 199), когда он будет построен.
- Получилась — строки `[мм:сс–мм:сс]` уходят в снимок и в описание модели; не получилась — ролик ложится данными API и причиной словами
  («что досталось + причина», слово владельца 2026-09-13).

## 2. Что считается готовым
Ролик с доступной расшифровкой отвечает на вопрос «на какой минуте говорится о …» меткой времени; ролик без неё ложится данными и честной причиной.

## 3. Чем доказывается — названо заранее
- **A:** эталонный ролик с субтитрами → в полном описании метки `[мм:сс–`; поиск по фразе из середины ролика находит объект.
- **B (негатив):** ролик под проверкой на ботов (`youtube-bot-check`) → данные API есть, расшифровки нет, причина названа — не «успех с пустым
  текстом».

## 4. На что опирается
195-4; федеральный 198 (для гарантии выше «лучшей попытки»); шаг 199 (запасной Chrome).

## 5. Чего не входит
Сам обход проверки YouTube и панель расшифровки (198) · запасной Chrome (199).
