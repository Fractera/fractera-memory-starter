# 195-10 — вкладка «Оценка» стенда ссылок: общий корпус случаев с подписью хранилища у каждого случая

## Откуда взялась задача
Порядок владельца 2026-09-14: «да, делай защиту от 403 и потом оценку». Решение на развилку (интерфейс выбора), дословно: **«Общий + подпись
(Recommended)»** — как у стенда объектов, один корпус и одна сводка (закон 189-6: числа хранилищ сравнимы); у каждого случая подпись
хранилища — на всех стендах сразу. Вынесено из 195-5 тем же приёмом, что поиск (195-8). Маршрутизация: исход A.

## 1. Что строится
- `app/[lang]/settings/_components/bench-cases.client.tsx` — в строке случая подпись хранилища из словаря (`words.stores[store]`);
  незнакомый ключ показывается как есть, а не пустотой.
- `app/[lang]/settings/_i18n/memory.i18n.ts` — `benchCases.stores` en/ru: граф · вектор · объекты · ссылки.
- `app/[lang]/settings/page.tsx` — «Оценка» стенда ссылок рисует `BenchCases`; «Навык» по-прежнему «строится» (195-5).
- `scripts/probe/link-verdict.mjs` — прибор.

## 2. Что считается готовым
На вкладке «Оценка» стенда ссылок видны все случаи корпуса с подписью хранилища; поиск ссылки появляется там с подписью «ссылки», и ему
можно поставить вердикт.

## 3. Чем доказывается — названо заранее
- **A (прибор через публичный адрес, без модели):** поиск ссылки без `probe` с меткой в вопросе → корпус (`bench-cases` GET) отдаёт случай
  `store: "link"` → вердикт `good` с причиной записан и читается обратно; в сборке страницы есть подписи хранилищ.
- **B (негатив):** вердикт `maybe` → `400 bad-verdict`, случай остаётся без вердикта; без секрета → `401`; уборка случая по метке, корпус до =
  после. **Глазами владельца** — вкладка «Оценка» стенда ссылок.

## 4. На что опирается
195-8 (поиск ссылок пишет случаи `store: "link"`).

## 5. Чего не входит
Отбор случаев по хранилищу (отвергнут решением владельца) · навык (195-5).
