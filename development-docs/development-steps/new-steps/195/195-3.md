# 195-3 — `keep_links {urls[], source, author, who}` в договоре: внешняя программа кладёт ссылки

## 1. Что строится
- `contract.mjs` — метод `keep_links`: `urls` (1–10), `source`, `author`, `who`; версия договора поднимается; `check-contract` зелёный.
- `server.mjs` — маршрут `/v1/keep_links` проводит тело по петле в дверь приёма ссылок с секретом машины (тот же приём, что
  `keep_object`); результат по каждой ссылке в порядке присланных: `messageId`, `object`, `title`, `summary`, `url` либо отказ с причиной.
- Страница API памяти — метод и параметры (переводы в `api.i18n.ts`), пример `curl`.
- 🔒 **Отказы метода называются в договоре поимённо, включая `page-refused`** — слово владельца 2026-09-14: «В нашем API для памяти у тебя
  есть варианты ошибок, стоит добавить ещё одно, не так ли?» Отказ появляется ВМЕСТЕ с методом, который его возвращает: без метода он
  описывал бы несуществующий путь. Там же — `url-forbidden`, `page-failed`, `page-timeout`, `browser-unreachable`, повтор ссылки (`existing`).
- 🛑 **Там же снимается висящее обещание:** описание `remember.media` в `contract.mjs` и его перевод говорят «страницы кладутся методом
  ссылок», а метода до 195-3 нет — фраза называет метод `keep_links` поимённо в тот же коммит, где он появляется.

## 2. Что считается готовым
Программа с ключом памяти одним вызовом кладёт несколько ссылок и получает судьбу каждой.

## 3. Чем доказывается — названо заранее
- **A (прибор снаружи):** `scripts/probe/v1-links.mjs` через `https://memory.aifa.dev/v1/keep_links` с ключом — две ссылки легли,
  у каждой `messageId`; `find_objects` находит одну по смыслу; уборка по метке.
- **B (негатив):** без ключа 401; ключ памяти не открывает дверь стенда напрямую; `http://127.0.0.1:3300/` в списке — отказ этой
  ссылки при успехе соседней; 11 ссылок — отказ с пределом.
