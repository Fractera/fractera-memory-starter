# 202-8 — у каждого раздела мастерской виден путь к его файлам в проекте

## Откуда взялась задача

Владелец оставил задачу 2026-09-15, смотря закрытый шаг 202, дословно: «попрошу тебя каждому элемента кроме терминал на вкладке показать
расположение в проекте этого файла. То есть нажали кнопку добавить задание открылась вкладка добавить задание и под заголовком рисуешь путь к
файлу в данном случае pre-steps.md. Задача показать как в проекте устроен архитектуру и расположение файло».
Маршрутизация: исход A — служит той же способности, что шаг 202 (мастерская разработки); шаг закрыт — возвращён план, добавлен подшаг,
шаг закрывается заново целиком.

## 1. Что строится
- `app/[lang]/build/_lib/build-sections.ts` — `BUILD_PATHS`: единственный источник путей разделов (терминала нет — по слову владельца).
- Под заголовком каждого раздела, кроме терминала, — строка пути (`data-build-path`): задание → `development-docs/development-steps/pre-steps/`
  и файл формата `README.md`; текущие шаги → `…/current-steps.md`; шаги → `…/development-steps/`; новые → `…/new-steps/`; завершённые →
  `…/completed-steps/`; навыки → `.claude/skills/`; инструкция → `CLAUDE.md`.
- Окно документа показывает путь открытого документа: `…/new-steps/202/`, `…/completed-steps/202-*.md`, `.claude/skills/<имя>/SKILL.md`.
- Допущение: владелец назвал «pre-steps.md», но `pre-steps` — папка; показывается папка и файл формата в ней.

## 2. Что считается готовым
У шести разделов и у каждого окна документа виден путь в проекте; у терминала пути нет.

## 3. Чем доказывается
- **A (прибор страницы на сервере):** у каждого раздела, кроме терминала, `data-build-path` с точным путём; путь существует на диске сервера.
- **B (негатив):** у терминала `data-build-path` = 0; окно шага и навыка показывает путь именно открытого документа.
