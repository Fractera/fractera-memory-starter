# 192-4 — три руки агента памяти

## 1. Что строится
`scripts/agent/memory-tools.mjs` — `find_objects({question})`, `open_object({id})`,
`keep_object({name, text, about})`; описания «назначение и цена, без поводов», как у соседей; все три
идут через собственные двери службы секретом машины.

## 2. Что считается готовым
MCP-сервер на машине отвечает `tools/list` с тремя новыми именами, и каждая рука даёт свой исход на
живом складе.

## 3. Чем доказывается — названо заранее
- **Плоскость A — JSON-RPC по stdio на сервере:** `tools/list` → 10 имён; `keep_object` → id;
  `find_objects` вопросом другими словами → этот id; `open_object` → текст.
  **Негативный контроль:** посторонний вопрос → «ничего подходящего ближе порога»; `open_object` по
  двоичному объекту → отказ рода, а не выдуманный текст; несуществующий id → «такого объекта нет».
- **Плоскость B — слой данных напрямую:** объект, положенный `keep_object`, есть в `GET /media`, его
  карточка — в `vectors` коллекции `memory-objects` с `ref_id` = id.

## 4. На что опирается
192-1, 192-2 (порог).

## 5. Чего не входит
Передача рук разбору фразы (`lib/think.mjs` получает имена параметром вызова — зовущего сейчас нет
ни у одной из рук хранилищ).
