# 192-1 — клиент объектов и три двери

## 1. Что строится
- `lib/fractera/objects.ts` — `keep()` (загрузка в медиатеку слоя данных + карточка в векторный
  склад, коллекция `memory-objects`, `refTable="media"`), `find()` (поиск карточек + сведения из
  медиатеки, порог), `open()` (карточка и текст текстового объекта с пределом), `status()`,
  `forget()` (по коллекции или по списку id — только свои).
- `app/api/fractera/object-test/route.ts` — `GET` что лежит · `POST` multipart `file` + `about` ·
  `DELETE` всё загруженное стендом или `{ids}`.
- `app/api/fractera/object-search/route.ts` — `POST {question, probe?}` → суждение с порогом,
  случай в корпус (`store: "object"`), кроме прогона прибора.
- `app/api/fractera/object-open/route.ts` — `POST {id}` → карточка + текст или отказ рода.
- Замок всех трёх — `benchGuard` (сессия архитектора или секрет машины).

## 2. Что считается готовым
Настоящий `.md` из FES, отправленный в `object-test` на сервере, находится `object-search` по
вопросу другими словами и открывается `object-open` своим текстом.

## 3. Чем доказывается — названо заранее
- **Плоскость A — живой вызов дверей на сервере секретом машины:** загрузка
  `agent-channel-routing.md` → `id`; поиск вопросом другими словами → тот же `id` первым.
  **Негативный контроль:** посторонний вопрос (рецепт борща) → `found:false`.
- **Плоскость B — слой данных напрямую, мимо наших дверей:** `GET /media` содержит строку с этим
  `id`; `GET /media/<id>/file` отдаёт байты, `sha256` совпадает с исходным файлом. Уборка: после
  `DELETE {ids}` строки нет, **а пять чужих объектов медиатеки на месте** (негатив уборки).

## 4. На что опирается
Шаг 189 (двери вектора, `benchGuard`, `noteRun`).

## 5. Чего не входит
Экран, прибор порога (до 192-2 стоит порог вектора 0.28 с пометкой «перемеряется»), руки агента.
