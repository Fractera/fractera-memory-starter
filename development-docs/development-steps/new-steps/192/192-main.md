## 3. Известные ограничения

| Инвариант | Что будет при нарушении |
|---|---|

| **порог близости — свойство корпуса** (закон 189-6) | порог вектора 0.28 на карточках объектов отсечёт верное или пропустит мусор молча |
| **прибор убирает по своей метке**, не `DELETE FROM` (закон 160/161) | в медиатеке живут файлы проекта и Telegram — стёрли бы чужое |
| **двери стенда — секрет машины, не ключ памяти** (189, §19) | вторая публичная дверь мимо договора |
| **договор не объясняет устройство** (LAWS, закон первый) | слово «объект/медиатека» в `contract.mjs` — утечка устройства; договор не трогается |

| **`runtime`/`dynamic` не объявлять** — `cacheComponents` | сборка падает |
| **ответ соседней службы читается целиком, не по коду HTTP** | `{ok:false}` при `200` сошёл бы за успех |
| **правки со слэшами — редактором, не `node -e`** | потерянный символ |
| **после `pm2 reload` ждать порт по факту** | гонка со стартом выглядит отказом двери |

## 4. Решения, принятые агентом по переданному полномочию

1. **Где живут объекты — медиатека слоя данных, а не свой склад в дереве службы** (развилка §16.8
   паспорта). Довод: граф и вектор ходят той же дорогой через слой данных — «стандарт графа и
   вектора» буквально это. Цена названа: объекты памяти видны в общем списке медиатеки платформы.
   Обратимость: весь доступ — один файл `lib/fractera/objects.ts`.
2. **Искать объект — по карточке в векторном складе**, коллекция своя, `refTable="media"`,
   `refId=<id объекта>`. У медиатеки поиска нет вовсе; карточка = имя + описание, у текстового
   объекта — ещё начало содержимого. Отсюда судья есть числом, как у вектора.
3. **Рук три, а не одна:** `find_objects({question})` · `open_object({id})` ·
   `keep_object({name, text, about})`. Довод за запись, которой у графа и вектора нет: там знание
   кладёт код памяти, а объект-ответ (§14.2 паспорта, «превращает в Markdown, кладёт в объектное
   хранилище и получает идентификатор») **сочиняет сам агент**. Без руки записи обещание инструкции
   «ответ бывает объектом» — способность, названная и отсутствующая.
   🛑 `keep_object` принимает **только текст** (Markdown): двоичный артефакт агент не порождает.
4. **Одна коллекция на стенд и агента** (`memory-objects`) — как у вектора сегодня (`memory-bench`).
   Долг изоляции корпусов уже назван в 189 и здесь наследуется, а не решается.
5. **`open_object` отдаёт содержимое только текстовым объектам и режет по пределу** с названным
   «показано N из M знаков»; двоичному — карточку и честное «содержимое этого рода не читаю».
6. **Прибор уносит свои объекты по их идентификаторам**, стенд — кнопкой «забыть всё загруженное
   стендом» по коллекции (коллекция и есть метка).

## 5. Наблюдаемые результаты

- на сервере дверь `object-test` принимает настоящий файл FES и отдаёт `id`; объект скачивается
  байт в байт; `object-search` на вопрос другими словами отдаёт этот `id` выше порога, а на
  посторонний — `found:false` с ближайшим числом;
- прибор на корпусе из `public/` печатает две группы близостей и порог из зазора;
- в разделе «Тест объектного хранилища» три вкладки, как у соседей;
- агент памяти по MCP видит три новые руки, `find_objects` находит, `open_object` читает
  текстовый и честно отказывает двоичному, `keep_object` возвращает идентификатор;
- навык `use-object-store` прогнан агентом с навыком и без, различие измерено признаками,
  названными заранее.
