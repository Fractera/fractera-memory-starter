## Дорогие измерения — не искать заново

- **служба живёт из `/opt/fractera/memory`, процесс pm2 `fractera-memory`, скрипт `server.mjs`;
  папка НЕ является клоном `fractera-memory-starter`** — её git смотрит в `Agent-Engineering-Infrastructure`.
  **Доставка только файлами:** `git -c core.autocrlf=false archive` → `scp-to-fractera.sh` →
  `tar -xzf` в `/opt/fractera/memory` → `npm run build` под `flock` → `pm2 reload fractera-memory`.
- после `pm2 reload` порт ждать **по факту** (`curl` до 200): здесь это 4 попытки по секунде;
- `claude` на сервере **2.1.267**; сессия — `--resume <session-id>` / `-c`, идентификатор из
  `--output-format json`; есть `--fork-session` и `--bg`.
- Память зовёт модель так: `claude -p <текст> --system-prompt <…> --model <…>`, **без истории**.
- Таймаут разбора внутри памяти — **120 000 мс** (`MEMORY_THINK_TIMEOUT_MS`); nginx не мешает.
- `/v1/*` памяти проверяет заголовок **`x-data-secret`** со значением `DATA_SECRET`.
- Граф умеет отдавать контекст **без вызова модели**: поле `only_need_context`.
- Квота подписки **одна** на память, бота и работу архитектора.
- 🛑 **Страница под `cacheComponents` обязана читать файл под `<Suspense>`.**
- 🛑 **Прибор, у которого два разных исхода дают одно число, измеряет не то, что утверждает**

## Шаг 184 — нить разбора (закрыт 2026-09-11)

Договор **2.1.0**: у `remember` появился `thread` — имя нити `claude -p`. Память возвращает его в
каждом ответе, где думала, и продолжает цепочку, когда его прислали обратно. Отрицание вывода
действует ТОЛЬКО в нити. Измерения — паспорт §18; прибор `scripts/probe/thread.mjs`.

**Дорогое измерение дня:** продолжение нити ДЕШЕВЛЕ нового вызова — 0.0289 → 0.0065 → 0.0036,
кэш часовой. Нить привязана к рабочей папке разбора: сменишь её — прежние нити не найдутся молча.
🛑 SSH-обёртка обрывает длинные вызовы: замеры `claude -p` запускать на сервере отдельно
(`nohup … &`) и читать файл.
